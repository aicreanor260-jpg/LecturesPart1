# CLAUDE.md — память проекта «Лекционные деки»

## Что это за репозиторий
Набор **самодостаточных анимированных HTML-презентаций** (одна глава = один `.html`-файл)
для курса по сигналам и связи (физический уровень OSI). Каждый файл открывается в браузере
офлайн, без сборки и без внешних зависимостей, кроме Google Fonts.

## Структура
- `decks/` — готовые деки: `glava2-modulation.html`, `glava3-sampling.html`, `glava4-manipulation.html` …
- `sources/` — исходники глав (`.docx` / `.pdf`), из которых строится содержание.
- `palettes/` — картинки палитр (скрин с hex-кодами), по одной на главу.
- `assets/memes/` — мемы (png/jpg), которые встраиваются в слайды в нужных местах.
- `reference-lectures/` — материалы других преподавателей для обогащения (НЕ копировать дословно, только идеи/факты).
- `.claude/skills/` — навыки (см. ниже).

## Главные правила (всегда соблюдать)
1. **Один HTML-файл.** CSS и JS внутри `<style>`/`<script>`. Картинки и шрифты — base64, чтобы работало офлайн.
2. **Никакого `localStorage`/`sessionStorage`** в логике слайдов (артефакты их режут). Стейт — в JS-переменных.
   Исключение: модуль рисования может предлагать опциональное сохранение пометок — только если явно попросят.
3. **Без выдуманного контента.** Не вставлять фейковые мемы-заглушки, пустые слайды-обещания «здесь будет…».
   Если мема для момента нет в `assets/memes/` — не выдумывать его, а оставить слайд без мема.
4. **Без AI-футуризма** в эстетике. Минимализм / журнальная вёрстка / брутализм.
5. **Личные контакты** на слайдах — только VKontakte и Telegram, без телефонов.
6. **Содержание строится из документа** главы максимально подробно: формулы крупные, с пошаговым выводом;
   на каждой диаграмме подписаны оси (`t`, `f`, `s(t)`, `|S(f)|`, `|H|`, `U` …); пустые места заполняются схемами.

## Как строить новую главу
Это делает навык **deck-builder** (`.claude/skills/deck-builder/`). Коротко:
читаем документ → вытаскиваем палитру из картинки (навык **palette-from-image**) →
берём свежую деку в `decks/` как структурный шаблон движка → перекрашиваем токены →
наполняем слайдами из документа → встраиваем мемы и интерактив → добавляем модуль
редактора/рисования → валидируем → кладём готовый `.html` в `decks/`.

## Проверка перед сдачей
- `node --check` по последнему `<script>` (синтаксис JS).
- число `<section class="slide">` = число `</section>`; нет дублей `data-label`.
- каждый `data-draw="X"` имеет зарегистрированный `drawers.X`; каждый `cv('id')` имеет `<canvas id="id">`.
- нет заглушек/`__PLACEHOLDER__`/обрывков SVG-путей.

## Стиль общения
Отвечать по-русски, по делу, без воды. Продолжать работу сразу, без лишних подтверждений.

## Деки по pptx (по итогам правок автора — подробно в `.claude/skills/deck-builder/reference/pptx-rules.md`)
- Порядок слайдов = порядок pptx; весь текст на месте; **конфигурации и выводы CLI дословно, ни строки не терять**.
- Ошибки самого pptx — не исправлять молча: перенести и спросить автора списком.
- Картинки pptx перерисовывать в стиле деки (консоль → терминал, таблицы → таблицы, схемы → SVG с теми же портами/IP/VLAN); подписей «Рисунок …» нет.
- Инфографики автора — вёрсткой на чистом фоне из папки «ФОН», сразу за своим слайдом; всё остальное — в их стиле.
- Сцены — по примеру этого слайда pptx, кабели в свои порты, ничего чужого.
- Финал: шпаргалка → задачи → тренажёры → живой тренажёр CLI (случайные задания, проверка, «Отправить кадр») → тест → итоги → финал.
- Перед сдачей: снять все слайды, проверить агентами по диапазонам pptx, прогнать тренажёр CLI, затем push в оба remote.
