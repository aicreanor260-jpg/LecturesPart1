о RIP
Протокол маршрутной информации (Routing Informational Protocol, RIP) -это самый простой протокол внутренней маршрутизации, работающий на основе дистанционно-векторного алгоритма и определённый в RFC 1058, RIPv2 и RFC 1388.
Протокол RIP использует алгоритм Беллмана-Форда для расчётов кратчайших путей. RIP не знает всю топологию сети и весь путь до адреса назначения, он знает только сведения, полученные от соседних RIP-маршрутизаторов: расстояние (дистанцию) до удалённой сети назначения; направление (вектор).
В качестве метрики (cost или стоимости) при выборе маршрута RIP использует количество переходов (hoр): чем короче путь, тем лучше маршрут. Максимальная длина маршрута равна 15 переходам, а 16 переходов означают, что сеть назначения недоступна.

Принцип работы

Принцип работы протокола на основе дистанционно-векторного алгоритма

Все протоколы маршрутизации разработаны для получения данных об удалённых сетях и быстрой адаптации к любым изменениям в топологии. Метод, который использует протокол, зависит от выбранного алгоритма и характеристик протокола.

Основные этапы

  • запуск протокола после включения питания;
  • сетевое обнаружение;
  • обмен данными маршрутизации;
  • сходимость сети.

Запуск протокола после включения питания

1 / 2Включение питания: таблицы маршрутизации пусты.Обнаружены напрямую подключённые сети — с количеством переходов 0.

Обнаружение напрямую подключенных сетей при включении электропитания рассмотрим на примере работы протокола RIPv2, сконфигурированном на каждом из трёх маршрутизаторов. При включении питания у каждого из маршрутизаторов ещё нет данных о топологии сети и о наличии устройств на других концах каналов. На данный момент каждому маршрутизатору доступна лишь информация из его собственного файла конфигурации, сохранённого в энергонезависимой памяти (ОЗУ).

После успешной загрузки маршрутизатор применяет сохранённую конфигурацию. Если IP-адресация настроена верно, первоначально маршрутизатор выполняет обнаружение напрямую подключённых сетей, интерфейсов, на которых размещены эти сети, а также с количеством переходов равным 0.

Эта информация добавляется в таблицу маршрутизации каждого маршрутизатора

  • Маршрутизатор R1: добавляет сеть 192.168.10.0/24, доступную через интерфейс gi1/0/2, и сеть 192.168.20.0/24 становится доступной через интерфейс gi1/0/1;
  • Маршрутизатор R2: добавляет сеть 192.168.20.0/24, доступную через интерфейс gi1/0/1, и сеть 192.168.30.0/24 становится доступной через интерфейс gi1/0/2;
  • Маршрутизатор R3: добавляет сеть 192.168.30.0/24, доступную через интерфейс gi1/0/2, и сеть 192.168.40.0/24 становится доступной через интерфейс gi1/0/1.

Получив эту исходную информацию, маршрутизаторы выполняют поиск дополнительных источников маршрутов для заполнения таблиц маршрутизации.

Сетевое обнаружение

1 / 3Перед первым обновлением: только напрямую подключённые сети.Маршрутизаторы рассылают пакеты обновления из всех включённых интерфейсов.Новые сети (красным) добавлены в таблицы с переходом 1.

Если настроен протокол маршрутизации, то маршрутизаторы начинают обмен данными о корректировке маршрутов для получения информации обо всех удалённых маршрутах. Маршрутизатор отправляет пакет обновления из всех включённых на нём интерфейсов. Обновление - это пакет протокола маршрутизации, который содержит данные из таблицы маршрутизации данного маршрутизатора.

Перед первым обновлением у каждого маршрутизатора в его таблице есть только данные о напрямую подключённых сетях и интерфейсы, через которые они доступны.

Маршрутизатор не только посылает пакеты обновления соседним маршрутизаторам, но и одновременно с этим принимает и обрабатывает пакеты обновления маршрутизации от соседей, работающих по такому же протоколу маршрутизации. Версия протокола маршрутизации имеет значение, и на всех маршрутизаторах она должна быть одинаковой.

Получив пакет обновления, маршрутизатор проверяет его на наличие данных о новых сетях. Все непрописанные в таблице маршрутизации сети маршрутизатор добавляет в свою таблицу.

Метод разделения
горизонта
Из-за медленной сходимости дистанционно-векторных протоколов может возникнуть петля маршрутизации, предотвратить которую возможно с помощью нескольких методов, один из них – метод разделения горизонта.
Метод разделения горизонта запрещает отправку данных из того же интерфейса, от которого они были получены. Например, R2 не отправляет обновление, содержащее сеть 192.168.10.0/24, из интерфейса gi1/0/1, так как R2 получил данные о сети 192.168.10.0/24 через этот же интерфейс gi1/0/1.
Маршрутизатор может использовать данные из таблицы маршрутизации для определения оптимального пути к адресу назначения только после завершения процесса сходимости всех маршрутизаторов в сети.
Сходимость

Обеспечение сходимости

Сходимость (Convergence) - это процесс согласования между маршрутизаторами сети доступных маршрутов, при котором маршрутизаторы самостоятельно и независимо друг от друга определяют влияние изменений в топологии на собственные маршруты и реагируют на изменения в топологии. Сходимость сети считается достигнутой, когда все маршрутизаторы получили полные и точные данные обо всей сети.

Значит, что когда таблица маршрутизации каждого маршрутизатора содержит все записи подсетей домена маршрутизации, тогда достигнуто состояние сходимости. До тех пор, пока сеть не достигнет сходимости, эта сеть не является полностью рабочей.

Время сходимости - время между моментом изменения состояния одной из линий связи и моментом, когда все маршрутизаторы рассчитают оптимальные пути и перестроят таблицы маршрутизации в соответствии с новой топологией.

Скорость распространения сходимости - это время, необходимое для отправки информации о маршрутизации от маршрутизаторов внутри сети. Чем быстрее выполняется сходимость, тем более эффективным является протокол маршрутизации. У протокола RIP низкая скорость сходимости, а современный протокол OSPF обеспечивает более быструю сходимость.

Алгоритм
Беллмана–Форда
Протокол RIP использует алгоритм Беллмана-Форда в качестве алгоритма маршрутизации. Основан на двух алгоритмах, разработанных в 1958 и 1956 г. Ричардом Беллманом (Richard Bellman) и Лестером Фордом-мл. (Lester Ford, Jr).
Различные протоколы маршрутизации используют различные алгоритмы для установки маршрутов в таблицу маршрутизации, отправки обновлений соседним устройствам и принятия решений об определении пути.
Протоколы IGRP и EIGRP используют алгоритм DUAL, разработанный доктором Дж. Дж. Гарсия-Луна-Асевес (SRI International).
В основе дистанционно-векторного протокола лежит алгоритм маршрутизации, который используется для протоколов маршрутизации, определяет процессы:
1
Обмен
механизм отправки и получения данных маршрутизации; алгоритм отправляет и принимает обновления.
2
Расчёт
механизм расчёта оптимальных путей и добавления маршрутов в таблицу маршрутизации; на каждом маршрутизаторе алгоритм самостоятельно выполняет вычисления и добавляет в таблицу маршрутизации новые данные.

Алгоритм Беллмана-Форда - это алгоритм поиска кратчайшего пути во взвешенном графе. За некоторое время алгоритм находит кратчайшие пути от одной вершины графа до всех остальных. Число на ребре — стоимость перехода.

Наша задача — найти кратчайшие пути от R1 до всех остальных вершин.

Алгоритм хранит для каждой вершины текущую оценку расстояния от R1. Сначала достоверно известно только расстояние от R1 до самого себя: оно равно нулю. Расстояния до остальных вершин обозначаются как бесконечность, то есть путь к ним пока не найден.

Для наглядности ниже каждый проход использует результаты предыдущего прохода. Так видно, как информация о пути продвигается по кольцу на одно ребро за раз.

Беллман–Форд

Алгоритм Беллмана–Форда

Первый проход. Алгоритм проверяет рёбра, выходящие из R1. Он находит путь R1 → R2 стоимостью 4 и прямой путь R1 → R4 стоимостью 10. Путь до R3 пока неизвестен: R1 и R3 не соединены ребром.

Второй проход. Теперь известна стоимость пути до R2, поэтому можно проверить переход от R2 к R3: 4+2=6. Значение для R3 меняется с бесконечности на 6. Можно также рассмотреть путь до R3 через R4, но его стоимость 10+3=13, поэтому сохраняется более короткий вариант через R2.

Третий проход. Через R3 найден новый путь до R4: 6+3=9. Он лучше прямого пути из R1 в R4, стоимость которого равна 10. Алгоритм заменяет оценку 10 на 9.

В таблицах метрика 0 означает, что сеть подключена к R1 напрямую; метрика 1 — путь через одного соседа; метрика 2 — через двух маршрутизаторов. Это удобная учебная запись. В самих сообщениях RIP стоимость непосредственно подключённой сети обычно указывается как 1, и при получении объявления сосед добавляет стоимость входящего участка. Поэтому нули из учебной таблицы не следует буквально переносить в RIP-пакет

После запуска и поднятия интерфейсов R1 уже знает три непосредственно подключённые сети. POST проверяет оборудование; маршруты появляются на основании состояния интерфейсов и их адресов, а не в результате POST.

Выход из строя канала связи

Рассмотрим сценарий, в котором вышел из строя канал связи между маршрутизаторами R1 и R3:

1 / 5Исходная схема: R1 — eth3 — eth1 — R3.Этап 1: интерфейсы down.Этап 2: метрика 16 в RIB.Этап 3: служебные сообщения по update timer.Этап 4: R2 и R4 заменяют маршрут — метрика 16.

Этапы

  • Этап 1: интерфейсы eth3 маршрутизатора R1 и eth1 маршрутизатора R3 перейдут в статус down.
  • Этап 2: маршрутизаторы R1 и R3 установят в RIB маршруту к сети 10.10.13.0/30 значение метрики 16.
  • Этап 3: в соответствии с истечением таймера (update timer), маршрутизаторы R1 и R3 сформируют служебное сообщение, включающее известную маршрутную информацию. В это сообщение включается путь к недоступной сети, причём метрика этого маршрута устанавливается равной 15.
  • Этап 4: маршрутизаторы R2 и R4 получают служебные сообщения от R1 и R3, инкрементируют значение метрики и помещают маршрут в RIB. В RIB маршрутизаторов R2 и R4 уже есть маршрут к сети 10.10.13.0/30 с метрикой 2, но т.к. источниками новых маршрутов с худшей метрикой являются те же маршрутизаторы, то маршрут в RIB будет заменён на маршрут с метрикой 16. Таким образом все маршрутизаторы сети получат информацию о недоступности канала связи.
Изменения топологии

Выход из строя канала связи

Время, в течение которого распространяется обновлённая информация зависит от размеров сети и зависит от значения update timer. Учитывая, что максимальный размер сети - 16 хопов, а update timer по умолчанию равен 30 секундам, то в худшем сценарии время распространения информации о недоступности канала связи будет равно 15*30 = 450 секунд.

Изменения топологии

Выход из строя маршрутизатора

Дополним схему двумя коммутаторами SW1 и SW2 и рассмотрим сценарий выхода из строя маршрутизатора R1.

При выходе из строя маршрутизатора R1, он не успевает отправить обновление маршрутной информации о своей недоступности маршрутизаторам R2 и R3. Кроме того, R2 и R3 не узнают о недоступности R1, поскольку они непосредственно подключены к коммутаторам SW1 и SW2, которые не поддерживают работу протокола RIP.

В этом случае, маршрутизаторы сети будут считать R1 доступным на протяжении timeout timer и будут использовать маршруты, связанные с R1. В частности, в таблице маршрутизации всех маршрутизаторов будут активны маршруты к сетям 10.10.12.0/30, 10.10.13.0/30 и 192.168.1.0/24.

Формат сообщения

Формат сообщения RIPv2

Протокол RIP работает поверх протокола UDP по известному порту 520. Максимальный размер датаграммы составляет 512 октетов. Он включает в себя только части датаграммы, при этом не учитываются заголовки IP и UDP. Команды, содержащие сетевую информацию, при необходимости позволяют разделить информацию на несколько датаграмм. Корректные результаты будут получены, даже если датаграммы обрабатываются по отдельности.

Общий формат сообщения протокола RIP версии 2 состоит из трёх частей: заголовок, аутентификация и маршрутная информация. Каждая часть содержит поля, в которых в двоичном или шестнадцатеричном виде указываются значения. Сообщение состоит из полей, в которых записываются различные значения.

Обозначения полей: Command (Команда). Определяет назначение датаграммы или тип пакета. Значение 1 - request, сообщение «Запрос», а значение 2 - response, указывает на сообщение «Ответ на запрос».

Формат сообщения

Формат сообщения RIPv2

Route Tag (Метка маршрута) - это атрибут маршрута, предназначен для разделения "внутренних" маршрутов RIP (маршруты для сетей внутри домена маршрутизации RIP) от "внешних" маршрутов RIP, которые могут быть импортированы из EGP или другого IGP протокола. Например, маршруты, импортированные из BGP должны иметь возможность устанавливать Route Tag либо в произвольное значение, либо в номер автономной системы, из которой был получен маршрут.

IP address (IP-адрес). Поле занимает 4 байта. В сообщении запрос (request) в данном поле содержит адрес сети, для которой необходимо определить маршрут. В сообщении ответ (response) в данное поле помещается адрес сети, которая является достижимой для источника данного сообщения.

Subnet Mask (Маска подсети). Поле занимает 4 байта, для RIPv2 тут размещается маска подсети, адрес которой расположен в поле IP Address, а для RIPv1 - в этом поле должен быть 0.

Next Hop (IP-адрес следующего перехода) - IP-адрес следующего перехода, на который следует пересылать пакеты к месту назначения, указанному в этой записи маршрута. Назначение этого состоит в том, чтобы исключить маршрутизацию пакетов через лишние переходы в системе. Значение 0.0.0.0 обозначает, что переходом к месту назначения является отправитель пакета. Это необходимо, если протокол RIP не может быть запущен на всех маршрутизаторах. У RIPv1 нет полей Subnet Mask и Next Hop.

Metric (Метрика) - это значение метрики или стоимости (cost), для протокола RIP это значение указывает на максимальное количество переходов от маршрутизатора к маршрутизатору на пути к цели. Значения поля от 1 до 15 (включительно) указывают на текущую метрику для пункта назначения, или 16, указывающее, что пункт назначения недоступен. При прохождении пакетом маршрутизатора к метрике прибавляется 1 и отправляется дальше к следующему соседу по пути к месту назначения.

<KEYCHAIN> - идентификатор списка ключей, задаётся строкой до 16 символов.

Объявление сетей

Включить анонсирование маршрутов, полученных альтернативным способом: напрямую подключенные сети, настроенные вручную или через протоколы BGP или OSPF

esr(config-rip)# redistribute connected [route-map <NAME>]

для анонсируемых, напрямую подключенных подсетей;

esr(config-rip)# redistribute static [route-map <NAME>]

для фильтрации и модификации анонсируемых статических маршрутов;

esr(config-rip)# redistribute ospf <ID> <ROUTE-TYPE> [[route-map<NAME>];
esr(config-rip)# redistribute bgp <AS> [route-map <NAME>]

для фильтрации и модификации анонсируемых BGP-маршрутов.

Параметры

  • <NAME> - имя маршрутной карты, которая будет использоваться, задаётся строкой до 31 символа;
  • <ID> - номер процесса, может принимать значение [1…65535];
  • <ROUTE-TYPE> - тип маршрута:
  • intra-area - анонсирование маршрутов OSPF-процесса в пределах зоны;
  • inter-area - анонсирование маршрутов OSPF-процесса между зонами;
  • external1 - анонсирование внешних маршрутов OSPF-формата 1;
  • external2 - анонсирование внешних маршрутов OSPF-формата 2.

Пассивный интерфейс

Как только конфигурация RIP выполняет команду network для подсети, протокол RIP сразу же начинает рассылку уведомлений со всех интерфейсов, входящих в эту сеть. Эти обновления могут быть нужны не на всех участках сети (в LAN не нужны RIP объявления сетей: во-первых, это лишний трафик, а во-вторых, небезопасно, так как обновление маршрутов может быть перехвачено любым устройством).

Команда passive-interface в режиме настройки интерфейса отключает обновления маршрутов в определенном интерфейсе.

Выключить анонсирование маршрутов на интерфейсах, где это не нужно (необязательно)

esr(config-rip)# passive-interface {<IF> | <TUN> }
  • <IF> - интерфейс и идентификатор;
  • <TUN> - имя и номер туннеля.

Защита от петель
Механизмы против петель: определения
1
Разделение горизонта (split horizon)
- это механизм, который запрещает маршрутизатору передавать пакеты через интерфейс, в котором они были получены.
2
Триггерные обновления (triggered update)
- это механизм, при котором маршрутизатор в случае ошибки маршрута увеличит метрику этого маршрута до 16 (то есть сделает маршрут недоступным и запрещённым) и немедленно отправит сообщение со своей таблицей маршрутизации, не дожидаясь, пока подойдёт время периодических обновлений. Это обновление присваивает маршруту статус удержания (holddown) в то время как протокол RIP пытается обнаружить альтернативный маршрут с лучшей метрикой.
3
Удержание измерений (holddown)
- это механизм, который стабилизирует маршруты, отказываясь принимать обновления маршрутов с большей метрикой для той же сети назначения на период, когда маршрут становится неактивным. Если в течение периода удержания исходный маршрут снова становится активным или маршрутизатор получает сведения о маршруте с более низкой метрикой, маршрутизатор устанавливает маршрут в таблице маршрутизации и немедленно начинает им пользоваться. Удержание используется для удаления неверных сведений о маршруте из всех маршрутизаторов в сети. Маршрутизатор обычно переходит в режим удержания при выходе из строя канала в маршруте. По умолчанию таймер удержания равен 6 интервалам update или 180 секундам.
4
Отравление или запрет маршрута (route poisoning)
- это установка метрики маршрута равной 16 для прекращения трафика по данному маршруту и немедленная отправка триггерных обновлений по событию, запрещая маршрут.
Таймеры

Таймеры

update - промежуток времени, через который осуществляется многоадресная рассылка маршрутной информации RIPv2 на IP-адрес 224.0.0.9. По умолчанию: каждые 30 секунд.

invalid - временной интервал корректности маршрутной записи без обновления, который должен быть не меньше 3 интервалов update, обычно равен от 3 до 6 update. По истечении времени этого интервала маршрут помечается как holddown (возможно недоступный). Если в обновлениях маршрутизатор получает такой маршрут, то маршрут отмечается как недоступный, но этот маршрут всё ещё участвует в отправке трафика. По умолчанию 180 секунд.

flush - временной интервал, в течение которого маршрут не удаляется из таблицы маршрутизации, а по истечении этого интервала времени производится удаление данного маршрута и установка альтернативного. По умолчанию: 240 секунд.

ESR# config
ESR(config)# router rip
ESR(config-rip)# timers

  invalid  Configure invalid timer
  update   Configure update timer

ESR(config-rip)# timers update
  12-65535  Time in seconds at which updates are sent

ESR(config-rip)# timers invalid
  12-65535  Time in seconds after which a route is declared invalid

ESR(config-rip)# timers flush
  12-65535  Amount of time in seconds that must pass before the route is removed from the routing

Для ускорения сходимости сети время таймера удержания (invalid) можно уменьшить, но осторожно. Таймер update является базовым, и относительно него устанавливаются остальные таймеры, но если менять таймеры, то: менять все таймеры и вручную каждый, а также на каждом RIP маршрутизаторе в рамках сети. Значения всех таймеров можно настроить в диапазоне от 12 до 65 535 секунд.
