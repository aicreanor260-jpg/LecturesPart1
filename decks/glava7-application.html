FTPпротокол передачи файлов

FTP (File Transfer Protocol) — протокол для передачи файлов между клиентом и сервером по модели клиент/сервер.

FTP-клиент

  • Запущенное на узле приложение для получения данных с сервера и отправки данных на сервер.
  • Устанавливает TCP-соединения с FTP-сервером.

Особенности

  • Для работы FTP необходимо два соединения: для команд и ответов — TCP-соединение, для передачи файлов — TCP-соединение.
  • Соединение для данных создаётся для каждого сеанса передачи и автоматически закрывается после её завершения.

FTP-сервер

  • На сервере должна быть запущена FTP-служба в виде приложения.
  • Обрабатывает команды клиента и обеспечивает передачу файлов.

Telnet использует TCP (порт 23) для передачи команд и данных между клиентом и сервером. Позволяет удалённо управлять сетевыми устройствами с помощью командной строки.

Основные особенности

  • Использует TCP (порт 23).
  • Позволяет управлять устройствами с помощью команд.
  • Не требует выделенного кабеля (в отличие от консольного порта), если IP-адрес сервера Telnet доступен.

Проблемы при росте сети

После перехода ARPANET на TCP/IP количество пользователей резко возросло. Поддерживать файл HOSTS.txt вручную стало очень сложно.

Типы DNS-запросов

Когда DNS-сервер не имеет записи запрашиваемого доменного имени, клиент может выполнить запрос в одном из двух режимов.

DNS — это распределённая система. База данных большинства DNS-серверов не содержит всех записей доменных имён.

Рекурсивный запрос

DNS-сервер запрашивает другие DNS-серверы и возвращает результат запроса DNS-клиенту.

Порядок действий

1Клиент отправляет запрос DNS-серверу.
2DNS-сервер запрашивает другие DNS-серверы.
3Другие DNS-серверы возвращают ответ DNS-серверу.
4DNS-сервер возвращает результат клиенту.

Итеративный запрос

DNS-сервер сообщает клиенту IP-адрес другого DNS-сервера, с которого клиент запрашивает доменное имя.

Порядок действий

1Клиент отправляет запрос DNS-серверу.
2DNS-сервер сообщает IP-адрес другого DNS-сервера.
3Клиент запрашивает имя у указанного DNS-сервера.
4DNS-сервер возвращает результат клиенту.

Доверенные и недоверенныеDNS-серверы

как это работает?

DNS — иерархическая система, в которой недоверенные серверы обращаются к доверенным за информацией о доменах и кэшируют ответы для ускорения последующих запросов.

Доверенный DNS-сервер

Хранит оригинальные записи о соответствии доменных имён и IP-адресов в рамках своей зоны ответственности и имеет право выдавать авторитетные ответы: информация актуальна и достоверна.

Недоверенный DNS-сервер

Не имеет оригинальных записей в зоне ответственности. Перенаправляет запросы к вышестоящим серверам и запоминает ответы; при повторном запросе выдаёт их из памяти, не загружая корневые серверы.

Пример работы DNS

Кэш DNS. Недоверенный сервер сохраняет ответ в памяти на время действия TTL и при повторном запросе выдаёт его из кэша.

Авторитетные и неавторитетные данные

Авторитетные данныеХранятся в базе данных в рамках своей зоны; за выдачу и достоверность отвечает доверенный сервер.
Неавторитетные данныеПолучены перенаправлением запроса к доверенному серверу и записаны в память локального DNS-сервера.

Этот IP-адрес уже используется. Клиент отправляет DHCPDECLINE, чтобы сервер назначил другой адрес.

Что такое конфликт IP-адресов?

Два устройства с одинаковым IP-адресом не могут корректно получать информацию от других узлов. Бывает при ручном назначении адресов разными администраторами без координации или без документации по инвентаризации адресов.

Зачем нужна проверка?

После DHCPACK клиент отправляет ARP-запрос на назначенный IP-адрес, чтобы убедиться, что он уникален в данном сегменте сети.

Что делать дальше?

Нет ARP-ответа — адрес свободен. Есть ответ — клиент уведомляет DHCP-сервер сообщением DHCPDECLINE и получает другой IP-адрес.

Как работает DHCP relay?

  1. 1
    Перехватывает широковещательные запросы от клиента (DHCPDISCOVER).
  2. 2
    Заменяет адрес источника на адрес своего интерфейса и добавляет его в поле GIADDR.
  3. 3
    Передаёт запрос DHCP-серверу одноадресно.
  4. 4
    Получает ответ от сервера (DHCPOFFER, DHCPACK).
  5. 5
    Отправляет ответ клиенту одноадресно, используя MAC-адрес клиента из сообщения.

Важно знать

Широковещательные сообщения DHCP не проходят через маршрутизаторы.
Клиент и сервер должны быть в одном широковещательном домене или использовать DHCP relay.
По полю GIADDR сервер определяет, какой пул адресов использовать для конкретной сети.

SMTP

Simple Mail Transfer Protocol
  • Отправка электронных сообщений.
  • От почтового клиента к серверу и между почтовыми серверами.
  • Передача писем между разными доменами.

IMAP

  • Получение писем.
  • Письма хранятся на сервере, клиент получает к ним доступ.

Post Office Protocol
  • Получение писем.
  • Письма загружаются с сервера на устройство (обычно с удалением с сервера).
  • Подходит для работы с почтой с одного устройства.
SMTP, IMAP и POP — основные протоколы, которые обеспечивают работу электронной почты.

SMTP

Simple Mail Transfer Protocol

Протокол для отправки электронных сообщений от клиента на почтовый сервер и между почтовыми серверами.

Структура SMTP-сообщения

ЗаголовокСтрого определённый формат (RFC 2822)
Тело сообщенияТекст произвольной длины

1 Установление соединения

  • При отправке почтовый клиент устанавливает соединение с почтовым сервером по SMTP.

2 Передача сообщения

  • Клиент отправляет сообщение на почтовый сервер.
  • Сервер проверяет, есть ли получатель в его списке: если да — доставляет; если нет — пересылает другому серверу (SMTP).

3 Временное хранение

  • Сервер назначения недоступен — сообщение хранится на сервере и периодически отправляется повторно.
  • Не доставлено за определённое время — возвращается отправителю с уведомлением.

4 Получение сообщения

  • Получатель забирает сообщение с сервера по IMAP или POP.
  • IMAP оставляет письма на сервере, POP загружает на устройство (обычно с удалением).
Поиск нужных почтовых серверов для пересылки происходит с помощью DNS — по записям MX.

POP получение электронной почты

Протокол POP (Post Office Protocol) используется для получения электронных сообщений с почтового сервера на устройство пользователя.

POP позволяет загружать письма с почтового сервера на локальное устройство, обычно с использованием TCP (порт 110) или защищённого POP3S (порт 995).

Этапы работы POP

  1. 1
    Отправитель отправляет письмо на адрес получателя (SMTP).
  2. 2
    Письмо доставляется на почтовый сервер и хранится там.
  3. 3
    Клиент устанавливает соединение с сервером (POP).
  4. 4
    Сервер отправляет приветствие и ожидает команд.
  5. 5
    Клиент проходит аутентификацию и запрашивает список писем.
  6. 6
    Клиент загружает сообщения на своё устройство.
  7. 7
    После получения сообщение удаляется с почтового сервера.

Работа протокола IMAP

получение и управление электронными сообщениями на сервере
IMAP (Internet Message Access Protocol) позволяет получать сообщения с почтового сервера, оставляя их копии на сервере.

Что такое IMAP?

Протокол прикладного уровня для получения и управления электронными сообщениями на почтовом сервере.

TCP 143IMAP использует порт TCP 143.

Как это работает?

  1. 1
    Отправитель отправляет письмо на почтовый сервер (SMTP).
  2. 2
    Письмо сохраняется на сервере получателя.
  3. 3
    Получатель подключается по IMAP и получает копию сообщения.
  4. 4
    Исходное сообщение остаётся на сервере, пока пользователь не удалит его вручную.

Особенности IMAP

Пользователь получает копию, оригинал остаётся на сервере.
Работа с письмами с нескольких устройств.
Изменения (прочитано, удалено) синхронизируются.
Удаление сообщения — и на устройстве, и на сервере.

Преимущества

  • Доступ к почте с любого устройства.
  • Синхронизация писем и папок.
  • Удобное управление сообщениями на сервере.
  • Для пользователей, работающих с почтой на нескольких устройствах.
IMAP — удобное решение для тех, кто хочет иметь доступ к своей почте с разных устройств, сохраняя письма на сервере.

NTP иерархическая структура серверов времени
