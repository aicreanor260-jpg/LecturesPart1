8.1 – 8.2 • Архитектура OSI

Значение и функции транспортного уровня

Транспортный уровень (4-й уровень модели OSI) связывает прикладной уровень с сетевой инфраструктурой, обеспечивает связь между приложениями на конечных узлах.

Ключевые задачи 4-го уровня
  • Отслеживание сеансов: Поддержка нескольких одновременных диалогов между приложениями.
  • Сегментация данных: Разбиение больших массивов информации на управляемые блоки.
  • Сборка сегментов: Восстановление исходного порядка данных на стороне получателя.
  • Адресация приложений: Идентификация процессов через номера портов.
8.2.1 – 8.2.2 • Механизмы передачи

Сегментация и мультиплексирование

Передача больших файлов одним куском заблокировала бы сеть. Сегментация делит данные на фрагменты (обычно до 1460 байт), а мультиплексирование чередует их в едином канале.

Преимущества сегментации

При передаче файла размером 300 КБ протокол разделяет его примерно на 206 сегментов (при MSS 1460 байт).

  • Повышение эффективности использования каналов связи.
  • При ошибке перепосылается только поврежденный сегмент, а не весь файл.
  • Параллельная работа множества сетевых приложений.

8.2.3 • Адресация

Порты и Сокеты (Sockets)

Для того чтобы доставленный пакет попал в нужное приложение, используются номера портов. Связка IP-адреса и номера порта образует Сокет.

Категории номеров портов (0–65535)
Известные (Well-Known): 0 – 1023
Зарезервированы для системных служб: HTTP (80), HTTPS (443), SSH (22), DNS (53).
Зарегистрированные: 1024 – 49151
Назначаются пользовательским приложениям (например, MS SQL 1433, MySQL 3306).
Динамические / Динамично-приватные: 49152 – 65535
Выделяются клиентам операционной системой на время сеанса.

8.3.3 • Flow Control

Скользящее окно и Управление потоком

TCP использует механизм Sliding Window, позволяющий отправлять группу сегментов без ожидания подтверждения на каждый из них, динамически регулируя размер окна (Window Size).

Готово к передаче. Окно определяет, сколько сегментов может быть отправлено в сеть до получения первого ACK.
8.3.4 • Закрытие сеанса

Завершение TCP-соединения (FIN / ACK)

Для корректного освобождения сетевых ресурсов TCP использует четырёхэтапную процедуру разрыва сеанса.

4 Этапа разрыва соединений
  1. FIN от Клиента: Клиент завершил отправку и посылает сегмент с флагом FIN.
  2. ACK от Сервера: Сервер подтверждает получение FIN (подключение переходит в полузакрытое состояние).
  3. FIN от Сервера: Сервер завершает свои процессы и отправляет свой FIN.
  4. ACK от Клиента: Клиент подтверждает FIN от сервера и после тайм-аута закрывает сокет.

8.4 • Протокол UDP

Протокол UDP (User Datagram Protocol)

UDP — протокол без установления соединения (Connectionless) с минимальным заголовком всего в 8 байт, оптимизированный для максимальной скорости.

Характеристики UDP
  • Без гарантии доставки: Потерянные датаграммы не перепосылаются.
  • Без контроля порядка: Пакеты могут приходить вне изначальной последовательности.
  • Без установления сеанса: Отправка начинается мгновенно без предварительных рукопожатий.
  • Минимальные задержки: Отсутствие накладных расходов на поддержание состояния.

8.5 • Сравнение протоколов

Сравнительный анализ: TCP vs UDP

Выбор между TCP и UDP зависит от требований конкретного приложения к надежности или скорости.

Параметр TCP (Transmission Control Protocol) UDP (User Datagram Protocol)
Соединение Устанавливает сеанс (Connection-oriented) Без установки соединения (Connectionless)
Надежность Гарантирует доставку всех байт Не гарантирует доставку (Best-effort)
Порядок пакетов Восстанавливает исходный порядок (Seq Num) Не восстанавливает порядок датаграмм
Управление потоком Есть (Sliding Window, Window Size) Отсутствует
Повторная передача Автоматическая при потерях Отсутствует (или на уровне приложения)
Сферы применения Web (HTTP/HTTPS), Email (SMTP), FTP, SSH VoIP, Онлайн-игры, DNS, DHCP, TFTP, Стриминг

Заключение и Ключевые выводы

1. Связующее звено

Транспортный уровень организует взаимодействие между прикладными сервисами и сетевым уровнем IP, сегментируя данные.

2. Адресация через сокеты

Связка IP-адреса и порта (Socket) позволяет однозначно идентифицировать конечное приложение на узле назначения.

3. TCP vs UDP Баланс

TCP выбирают ради абсолютной надежности и контроля потока; UDP — ради максимальной скорости и минимальных задержек.
