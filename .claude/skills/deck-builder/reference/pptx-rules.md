# Деки по pptx: правила, выведенные из правок автора

Обязательны для любой деки, которая строится из pptx (и для docx-глав, где применимо).
Перекрывают общие указания SKILL.md при противоречии. Источник — реальные переделки 2.2 «Базовая настройка» и «VLAN».

## 1. Содержание = pptx, без самодеятельности
- **Порядок слайдов строго как в pptx.** Модуль деки пишется по номерам слайдов (`# ---- pptx N`). Нельзя собирать деку
  из кусков другой деки и «тасовать» — слайды «разбегаются», логика лекции рвётся.
- **Весь текст слайда pptx — на слайде деки.** Не сокращать, не пересказывать «своими словами». Перегруженный слайд —
  разбить на 2 слайда с тем же заголовком, в том же порядке.
- **Конфигурации и выводы CLI — дословно и полностью.** Ни одной строки не выбрасывать, не «улучшать», не менять порты/VLAN/IP.
  Склеенные в pptx строки разбить на команды, не меняя их. Ради этих конфигураций деку и делают.
- **Ошибки самого pptx** (опечатка в адресе, `privilege 15` вместо 1, пропущенная команда) — сначала перенести как есть
  и **спросить автора** списком; исправлять только после ответа.
- **Подписи «Рисунок 2.x.x …» не выводить** нигде (ни под картинкой, ни внутри схемы). Ссылки «(см. рисунок …)» из текста убирать,
  смысл не трогать.
- **Ничего не добавлять от себя в материал лекции.** Сцены, задачи, тесты — только на фактах этой pptx
  (ошибка была: «0 и 4095 зарезервированы», чужие VLAN 25/26, «физически — дорого»).

## 2. Картинки pptx — перерисовать в стиле деки, не вставлять фото
| Что в pptx | Как в деке |
|---|---|
| скриншот консоли | терминал `term()` построчно: хеши, даты, пустые строки, звёздочки — как на картинке |
| команды в тексте | `conf()` (приглашение приглушено, команда подсвечена) |
| таблица MAC / show vlan | таблица `mtables()` / моноширинный вывод |
| блок-схема прохождения кадра | `flow()` — блоки сверху вниз |
| кадр `[A \| B \| C]` | `fr()` — цветные поля |
| схема топологии | SVG в стиле деки; устройства — иконки из инфографик автора; **те же устройства, порты, IP, VLAN, направления**, без выдуманных адресов |
| окно программы / Web | HTML-окно в стиле деки с теми же полями и значениями |
| инфографика автора | вёрстка 1:1 поверх **чистого фона** из папки `ФОН` (`_dk_rep/<имя>.py`), сразу за своим слайдом |

Расшифровку скриншотов делать отдельным шагом в `_dk_tx.py` (агент), затем сверять.

## 3. Стиль
- Стиль деки берётся из инфографик и фонов автора (папка с фото к лекции). Всё — сцены, схемы, окна, панели — в этом стиле.
  Неоновые/«чужие» примитивы поверх фона без панели = «не в стиле презы».
- SVG-сцены — на панели деки; ПК/коммутаторы/телефоны — иконками из инфографик (фон вырезки — прозрачный).
- Текст SVG: цвет через `style="fill:…"` (общий CSS красит `svg.fig text` в белый). `<b>` внутри SVG запрещён — ломает разбор HTML.
- Шрифт заголовков с кириллицей проверять глазами (Pixelify Sans читается плохо → Press Start 2P).
- Текст крупный: проектор. Пустая нижняя половина слайда = увеличить кегль/схему.

## 4. Сцены (анимации по шагам)
- Каждый кабель — **в свой порт**, не в центр коммутатора; кабели за корпусом.
- Сцена повторяет **пример этого слайда pptx**: те же порты (Gi0/1, Gi0/24…), MAC, VLAN, порядок шагов.
  Сцену из другой деки брать только если она не противоречит pptx; иначе — писать заново (`_vl_scn.py`).
- Ни одной лишней сущности (лишний trunk B, «аксиомы» не к месту, чужие номера).

## 5. Финал деки (как обычно)
Шпаргалка (команды строго из pptx в том же синтаксисе) → итоговые задачи (ввод ответа + разбор) →
тренажёры → **тренажёр CLI** → тест (≈4 вопроса на слайд, общий счёт) → «Что запомнить» → «Финал» (VK, Telegram).
- **Тренажёр CLI** — живая консоль (`_dk_cli.js`): старт `switch#`, `configure` → `(config)#`, `interface …` → `(config-if)#`,
  приглашение меняется по режимам, ошибки как на устройстве, `show running-config` / `show vlan`.
  Кнопки: «Обновить задание» (случайные порты/VLAN/имена), «Проверить» (по итоговому состоянию, ✓/✗ по пунктам),
  «Решение», мини-проверка («Подключиться заново» — баннеры и приглашение; «Отправить кадр» — дойдёт ли).
  Новые задания — шаблоном в `TASKS[deck]` (gen / text / sol / checks / send).

## 6. Проверка перед сдачей (обязательно)
1. Сборка + `node --check`, число секций, нет дублей `data-label`, нет «Рисун» и `&lt;span` в тексте.
2. Снять **все** слайды (playwright, шаги раскрыты) и просмотреть листы.
3. **Агенты-проверяющие по диапазонам слайдов pptx** (только отчёт): порядок, полнота текста, конфигурации построчно,
   выводы vs скриншоты, логика схем и сцен, ответы тестов. Расхождения исправить, ошибки pptx — вопросом автору.
4. Тренажёр CLI: прогнать решения всех шаблонов через консоль (≥10 случайных на слайд) — все «Задание выполнено».
5. build → commit → push в оба remote (preza-lekciy и LecturesPart1) без вопросов.
