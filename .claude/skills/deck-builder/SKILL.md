# Сборщик лекционных дек

## 0. Перед началом
- **Если источник — pptx: сначала прочитать `reference/pptx-rules.md` и выполнять его целиком** (порядок слайдов pptx, конфигурации дословно, картинки перерисовать в стиле, без «Рисунок», финал с тренажёром CLI, проверка агентами). Он важнее остальных пунктов этого файла.
- Прочитать **весь** исходный документ из `sources/` (docx/pdf). Для pdf — извлечь текст и подписи к рисункам;
  это каркас содержания, ничего не выдумывать сверх него.
- Открыть `reference-lectures/` и бегло просмотреть материалы по теме — брать оттуда **идеи, факты, удачные примеры**,
  но НЕ копировать формулировки дословно (перефразировать).
- Найти картинку палитры в `palettes/` для этой главы → запустить навык **palette-from-image** и получить токены.
- Взять **самую свежую деку** в `decks/` как структурный шаблон движка (CSS-каркас + JS-движок + рисовалки):
  копировать структуру, не изобретать новый движок.

## 1. Дизайн-язык (неизменный)
- Драматический типографический контраст: serif-заголовки (Playfair Display), Inter — текст, JetBrains Mono — формулы/код.
- Асимметричные CSS-Grid раскладки (`.split.s55/.s64`), много воздуха, журнальная вёрстка, минимализм/брутализм. **Без AI-футуризма.**
- Фирменный элемент — вогнутая четырёхлучевая звезда-искра (symbol `#spark`), повторяется в киккерах и списках.
- Верхний и нижний «рельсы» (toprail/botrail), прогресс-бар, счётчик слайдов, навигация стрелками/пробелом/свайпом.
- Каждая глава — свой колор-палитра из своей картинки. Перекраска делается **только** через значения CSS-переменных в `:root`
  и объект `PAL` для canvas; имена токенов НЕ меняются (низкий риск): `--void/--void2/--panel` (фон),
  `--wheat` (светлый текст и плашки), `--ink` (тёмный текст на плашке), `--terra/--terra-d` (главный акцент),
  `--cyan/--teal` (вторичный акцент), `--espresso` (тёмная карточка), `--tan/--tan-d` (приглушённый текст), `--hair` (линии).
- `field`-градиент и `PAL` тоже перекрасить под палитру.

## 2. Наполнение слайдами (из документа, подробно)
- Идти по разделам документа по порядку: вступление → теория → схемы/элементы → формулы → примеры → сравнение → итог → обозначения → вопросики.
- **Формулы крупные**, с пошаговым выводом; блок `.formula` с подсветкой `.c` (вторичный) и `.t` (главный акцент).
- **Подписи осей обязательны** на всех диаграммах: `t`, `f`, `s(t)`, `|S(f)|`, `|H|`, `U` и т.п.
- Пустые места на текстовых слайдах заполнять схемой (inline-SVG) или анимированным canvas.
- Поэлементный разбор схем («что это такое и как влияет на сигнал») — отдельными слайдами, когда уместно.
- Числовые **примеры** — отдельными слайдами: дано → расчёт по строкам → вывод (см. существующие «Пример · …»).
- Финал — слайд «Вопросики» с интерактивными карточками `.qa` (`onclick="this.classList.toggle('open')"`).

## 3. Мемы (по требованию, без подделок)
- Брать файлы только из `assets/memes/`. Встраивать как base64 в `<img>` в конкретный смысловой момент.
- **Запрещено** выдумывать мем, ставить заглушку или «обещать» мем, которого нет. Нет файла — нет мема.

## 4. Интерактив и анимация (canvas-движок)
- Все рисовалки регистрируются в реестре `drawers.X` и вызываются по `data-draw="X"` при показе слайда.
- Каждый `cv('id')` требует `<canvas id="id">`. Ползунки — `bindRange('id', fn)` с гардом `if(el)`.
- Анимация: `raf = requestAnimationFrame(frame)`, остановка — общий `stopAnim()` при смене слайда.
- Q&A-карточки: inline `onclick="this.classList.toggle('open')"` + CSS `.qa`/`.qa.open .a`.

## 5. Встроенный редактор и рисование (добавлять в каждую деку)
Вставить модуль из `reference/draw-edit-module.html` целиком перед `</body>` (после основного `<script>`).
Он даёт прямо в браузере поверх слайдов:
- **Перо/маркер** для рисования по слайду (Canvas API, без внешних либ, офлайн), выбор цвета и толщины, ластик, очистка.
- **Режим правки текста** (`contentEditable` для активного слайда) — поправить опечатку на лету.
- Пометки хранятся в памяти по индексу слайда (без `localStorage`). Если пользователь явно попросит сохранять —
  можно включить `localStorage` ТОЛЬКО для слоя пометок и только при открытии файла напрямую в браузере.
Горячие клавиши и панель описаны внутри модуля. Цвета панели брать из палитры главы.

## 6. Сборка и валидация (workflow)
1. Строить файл инкрементально в рабочей папке; наполнять через маркер `<!--SLIDES-->` (вставлять батчи перед ним).
2. Валидация: вынуть последний `<script>` и прогнать `node --check`.
3. Проверить: число `.slide` = число `</section>`; нет дублей `data-label`; все `data-draw` зарегистрированы;
   все `cv()` имеют canvas; нет `__PLACEHOLDER__` и обрывков SVG-путей (`... `).
4. Убрать маркер `<!--SLIDES-->`, положить готовый `.html` в `decks/`.
См. полный список в `reference/checklist.md`.

## Антипаттерны (никогда)
- Выдуманные мемы/заглушки/обещания будущего контента.
- `localStorage` в логике слайдов. Внешние JS-зависимости (кроме Google Fonts).
- Менять имена CSS-токенов при перекраске. Диаграммы без подписей осей. AI-футуризм-эстетика.
- Телефоны в контактах (только VK и Telegram).
